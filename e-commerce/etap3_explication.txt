EXPLICATION DE L'ÉTAPE 3 : GESTION DU PANIER ET PRINCIPES SOLID

Ce document explique comment nous avons implémenté le panier en respectant une architecture professionnelle.

1. ARCHITECTURE ET PRINCIPES SOLID
-----------------------------------
Le but était de ne pas coupler le code à une seule méthode de stockage (comme la session).
- S : Single Responsibility (Le CartHandler ne gère que la logique de haut niveau).
- O : Open/Closed (On peut ajouter une nouvelle méthode de stockage sans modifier le CartHandler).
- D : Dependency Inversion (Le Handler dépend d'une interface, pas d'une classe concrète).

2. LES COMPOSANTS CRÉÉS
-----------------------
- CartInterface : Le contrat. Toute méthode de stockage doit avoir ces fonctions (addProduct, getCart...).
- SessionCartService : L'implémentation réelle qui utilise la session Symfony.
- ApiCartService : Une simulation pour prouver qu'on peut changer de système facilement.
- CartHandler : Le service utilisé par le contrôleur. Il reçoit l'interface via le constructeur.

3. L'INJECTION DE DÉPENDANCES ET AUTOWIRE
------------------------------------------
Comme nous avons deux services (Session et API) qui implémentent la même interface, Symfony a besoin d'aide pour savoir lequel choisir.
Nous avons utilisé l'attribut :
#[Autowire(service: 'App\Service\SessionCartService')]

Cela permet de changer de stratégie de stockage en changeant juste une ligne de code !

4. FONCTIONNEMENT DU PANIER
---------------------------
- Les objets Cart et CartItem sont des "Modèles" (DTO).
- Ils ne sont pas enregistrés en base de données (MySQL) pour le moment, mais stockés sous forme d'objets sérialisés dans la session de l'utilisateur.

5. MODIFICATIONS UI
-------------------
- product_details.html.twig : Ajout d'un formulaire <form> avec une méthode POST pour envoyer l'ID du produit et la quantité au contrôleur.
- cart.html.twig : Utilisation de boucles Twig pour afficher le contenu dynamique de la session.

--------------------------------------------------
ÉTAPE 3 VALIDÉE : Le système de panier est extensible, robuste et suit les standards de développement Symfony modernes.
